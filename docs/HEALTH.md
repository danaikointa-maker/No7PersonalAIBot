# 🩺 สุขภาพข้อมูล (Data health)

หน้า **ตารางนัด → งานที่ต้องทำ** มีปุ่ม **🩺 ตรวจสุขภาพข้อมูล** เพื่อวิเคราะห์ข้อมูลที่เก็บไว้ในเครื่อง แล้วแสดงคะแนน 0–100, เกรด A–D, รายการที่พบ และคำแนะนำในแชท การตรวจเกิดในเบราว์เซอร์และไม่ส่งข้อมูลไปยังเซิร์ฟเวอร์หรือ AI

## สิ่งที่ตรวจ

| รายการ | วิธีตรวจ | ลบอัตโนมัติ? |
| --- | --- | --- |
| ความจำซ้ำ | normalize ตัวอักษร ตัดช่องว่าง/เครื่องหมาย แล้วจัดกลุ่ม; เก็บรายการใหม่สุดไว้ | ลบได้เมื่อผู้ใช้กดยืนยัน |
| สิ่งที่ต้องทำซ้ำ | normalize ข้อความ; เก็บรายการใหม่สุดไว้ | ลบได้เมื่อผู้ใช้กดยืนยัน |
| โน้ต/สิ่งที่ต้องทำว่าง | ข้อความว่างหรือมีแต่ช่องว่าง | ลบได้เมื่อผู้ใช้กดยืนยัน |
| ความจำเก่า | ไม่ปักหมุด, ไม่ถูกใช้, เก่ากว่า 90 วัน | ไม่ลบ — แสดงเป็นคำแนะนำเท่านั้น |
| งานเกินกำหนด | งานที่ยังไม่เสร็จและกำหนดส่งก่อนเวลาปัจจุบัน; เกิน 14 วันเป็นระดับสูง | ไม่ลบ |
| งานไม่มีกำหนด | งานที่ยังไม่เสร็จและไม่มีวันครบกำหนด | ไม่ลบ |
| นัดเก่า | เวลาเริ่มก่อนเวลาปัจจุบัน | ไม่ลบ |

ระดับปัญหา high / medium / low หักคะแนนตามความรุนแรงและจำนวน โดยคะแนนถูกจำกัดในช่วง 0–100: A ≥ 90, B ≥ 75, C ≥ 60, D < 60 คะแนนเป็นตัวชี้นำ ไม่ใช่การตัดสินคุณค่าหรือความถูกต้องของข้อมูล

## การล้างอย่างปลอดภัย

การตรวจไม่ลบอะไรเอง ปุ่ม **🧹 ล้างรายการซ้ำ/ว่าง** จะเปิดการยืนยันพร้อมจำนวนแยกประเภท และล้างเฉพาะรายการซ้ำ/ว่างที่การตรวจรอบนั้นทำเครื่องหมายไว้ (เก็บรายการล่าสุดในกลุ่มซ้ำ) ความจำเก่า งาน และนัดหมายไม่อยู่ในขอบเขตการล้าง ข้อมูลการ์ดจะถูกคำนวณใหม่หลังล้าง

หลังล้างจะมีปุ่ม **↶ ย้อนกลับการล้าง** ให้ใช้ภายใน 30 วินาที โดยเก็บ snapshot ล่าสุดไว้ในหน่วยความจำของหน้าเว็บเท่านั้น (ไม่เขียนสำเนาสำรองเพิ่มลง localStorage และหายเมื่อ reload/ปิดหน้า) Undo จะไม่เพิ่มความจำที่มี id/ข้อความเดิมอยู่แล้ว และจะเก็บรายการปัจจุบันไว้ก่อนเมื่อนำโน้ต/สิ่งที่ต้องทำกลับตำแหน่งเดิม การกดล้างครั้งใหม่แทนที่โอกาส Undo เก่า

ปุ่มและการ์ดสุขภาพเปลี่ยนภาษาตาม ⚙️ → ภาษา UI; การสแกนไม่ต้องทำใหม่

## ประวัติและแนวโน้ม 7/30 วัน

เมื่อผู้ใช้กดสแกน ระบบบันทึกหรือแทนที่ snapshot ตามวันปฏิทินท้องถิ่นของเครื่องใน `no7.health.history.v1` โดยใช้ date key เดียวกับตัวกรอง 7/30 วัน ดังนั้นการข้ามเที่ยงคืน UTC จะไม่ทำให้ snapshot ไปอยู่ผิดวันในพื้นที่ของผู้ใช้ เก็บ summary metrics ต่อเนื่อง ไม่ตัดวันเก่าอัตโนมัติ แสดงกราฟคะแนน, เกรด, จำนวนปัญหา และส่วนต่างจากการสแกนครั้งก่อนในช่วง 7/30 วัน ปุ่ม **ล้างประวัติ** ลบเฉพาะข้อมูลสรุปนี้หลังผู้ใช้ยืนยัน

ประวัติเก็บเฉพาะ `{ date, score, grade, issues: { high, medium, low } }` พร้อม `schema: 1` — ไม่เก็บข้อความความจำ, โน้ต, งาน, นัดหมาย หรือรายละเอียดปัญหา ประวัติอยู่ใน localStorage ของเครื่องและไม่ได้ซิงก์/ส่งไป AI; การสแกนรอบเดิมในวันเดียวกันจะแทนที่ ไม่เพิ่มแถวซ้ำ เมื่อผู้ใช้กดส่งออกข้อมูลสำรองทั้งแอป ประวัติสรุปนี้รวมในไฟล์โดยไม่มีฟิลด์อื่น และกู้คืนหลังยืนยันร่วมกับข้อมูลชุดอื่น

ตัวกรอง **7 วัน / 30 วัน** เปลี่ยนกราฟและรายการทันทีโดยไม่สแกนหรือเขียน storage; สรุปช่วงแสดงจำนวนวันมีข้อมูล, ค่าเฉลี่ย, สูงสุด/ต่ำสุด และ delta จากคะแนนแรกถึงล่าสุดในช่วงที่เลือก โดยประวัติ summary เก่ากว่ายังคงอยู่ในเครื่อง

ผู้ใช้สามารถกด **⬇️ Markdown**, **⬇️ CSV** หรือ **⬇️ JSON** เพื่อดาวน์โหลด snapshot สรุปทั้งหมดด้วยตนเอง (CSV มี BOM และป้องกัน formula injection); JSON เกิน 20 MiB จะไม่สร้างไฟล์แต่ประวัติในเครื่องคงเดิม หากดาวน์โหลดไม่ได้จะคัดลอกไป clipboard ตาม fallback เดิม ไม่มีการส่งข้อมูลอัตโนมัติ

ปุ่ม **⬆️ นำเข้า JSON** รับเฉพาะ envelope `no7-health-history` schema 1 ที่ส่งออกจากระบบนี้ ตรวจรูปแบบ/วันที่/จำนวนรายการก่อน แล้วแสดง preview เพิ่ม/แทนที่/คงเดิมก่อนยืนยัน ข้อมูลจากไฟล์จะถูกรวมตามวัน (ไฟล์นำเข้าชนะเมื่อวันตรงกัน) และเก็บเฉพาะ fields ที่อนุญาต; ฟิลด์อื่นถูกทิ้ง ไม่มีการเขียน storage ก่อนผู้ใช้ยืนยัน ไฟล์ต้องไม่เกิน 20 MiB และ 1,000,000 snapshots; ไม่มีการตัดประวัติเก่าที่มีอยู่

## API

`analyzeHealth({ facts, notes, todos, tasks, events, now, staleDays, unusedDays })` คืน `{ now, score, grade, gradeLabel, counts, issues, cleanup, suggestions, markdown }`.

`applyCleanup(cleanup, { facts, notes, todos })` คืนสำเนารายการหลังล้างและจำนวนที่เอาออก โดยไม่แก้ข้อมูลต้นทาง ส่วน `healthMarkdown(report, 'th' | 'en')` สร้างรายงานให้อ่านหรือส่งเข้าแชทได้

`recordHealthSnapshot(history, report, now)` เพิ่ม/แทนที่สรุปรายวันโดยไม่ตัดวันเก่า; `normalizeHealthHistory`, `readHealthHistory`, `writeHealthHistory`, `clearHealthHistory` จัดการข้อมูล versioned; `healthTrend` สรุปส่วนต่าง; `renderHealthHistory` แสดงกราฟ SVG และรายการข้อมูลสรุปเฉพาะช่วงที่เลือก

`healthHistoryCsv(history, { lang })`, `healthHistoryMarkdown(history, { lang, now })` และ `healthHistoryJson(history, { now })` ส่งออกเฉพาะ snapshot ที่ normalize แล้ว (ไม่รับรายละเอียดรายการส่วนตัว) JSON ใช้ envelope `{ format: 'no7-health-history', schema: 1, exportedAt, snapshots }`. `parseHealthHistoryBackup`, `planHealthHistoryImport` และ `applyHealthHistoryImport` ตรวจไฟล์, ทำ preview merge แบบไม่เขียนข้อมูล และบันทึกหลังยืนยัน

ไฟล์: `web/src/core/health.js` · tests: `tests/health.test.js` · UI: `web/src/main.js`

## ข้อจำกัด

- ความหมายของความซ้ำขึ้นกับข้อความที่ normalize แล้ว; ข้อความต่างกันเล็กน้อยอาจเป็นคนละรายการ
- ความจำเก่าคือคำแนะนำตาม timestamp/ตัวนับการใช้งาน ไม่ได้หมายความว่าความจำนั้นไม่มีประโยชน์
- คะแนนเป็น heuristic สำหรับตรวจคร่าว ๆ ไม่ใช่ตัวตรวจคุณภาพเชิง semantic
